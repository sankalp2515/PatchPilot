# Demo scripts

Two variants stay below three minutes. Use actual on-screen runs; keep replay and live mode labels visible. Hide credential settings, private terminal history and unrelated account data. Pre-open the relevant partner evidence pages for a smooth demonstration. Trim waiting time transparently without implying that a replay is a live model call.

## NeatHack — 2:50

| Time | Screen/action | Narration |
|---|---|---|
| 0:00–0:15 | Homepage → Open workspace | “PatchPilot investigates an API migration and keeps the evidence with its repair. A moved payment field can break a small adapter; a plausible patch can still miss response shapes.” |
| 0:15–0:35 | Recovery example; mode clearly Recorded replay | “This is a deterministic historical Stripe replay. Here is our adapter and five protected expected outputs. The agent saves its plan and reproduces the failure.” |
| 0:35–0:55 | Evidence/version and source excerpt | “In live mode SerpApi discovers these official vendor pages. Only fetched, version-specific evidence can support a patch; snippets are not enough.” |
| 0:55–1:20 | Attempts, diff and failed first case results | “The first proposal handles too little. Actual failed cases feed the next attempt; the contract does not change to make the patch pass.” |
| 1:20–1:40 | Acceptance, audit and Repair proof | “The final replay passes five supplied cases and twenty separate local counterexamples. That audit is specific to this Stripe contract. Hashes bind the input, sources and patch, without claiming universal correctness.” |
| 1:40–2:00 | neatlogs actual traces and comparison file | “neatlogs traces research, proposals and verification without user payload capture. This preserved adapter passed five supplied cases but six of twenty audit cases; the enhanced replay passes all twenty. It is an adapter comparison, not an LLM accuracy benchmark.” |
| 2:00–2:20 | Entire actual checkpoint/commit | “Entire preserves this real read-only design review attached to a commit. Hooks were enabled after this chat began, so the session was imported retrospectively; earlier development was not continuously captured.” |
| 2:20–2:38 | cfo.ai saved scenario table | “cfo.ai stores three launch scenarios. Readback covers forty-five selected cells with no formula errors. Prices, customers and costs are editable USD hypotheses, not traction.” |
| 2:38–2:50 | Download report; repository quickstart | “Run the local replay without keys. Review the code, evidence and tested boundaries before applying it. The public repository contains the implementation and partner proof.” |

If showing the live run too, shorten replay/partner transitions and keep the total under three minutes. Do not hide unresolved live failures.

## SerpApi — 2:45

| Time | Screen/action | Narration |
|---|---|---|
| 0:00–0:15 | Homepage → workspace | “PatchPilot repairs a broken API adapter by researching the migration before changing code.” |
| 0:15–0:35 | Stripe example, Live search + AI, start | “This uses a real SerpApi search and model request against historical sanitized response fixtures. No payment transaction is created.” |
| 0:35–1:00 | Activity: actual Google query and discovered source | “The agent searches the target version and failing field through SerpApi. The discovery record preserves query provenance; search snippets only identify source candidates.” |
| 1:00–1:20 | Fetched Stripe page, version and literal citation | “The source is acquired from an allowlisted official host. The quote must literally occur in the captured text and address the incident.” |
| 1:20–1:45 | Proposed diff and attempt feedback | “The model proposes one constrained Python function. Unsupported code or citations are rejected; failed results can drive another attempt.” |
| 1:45–2:10 | Baseline versus final cases; applicable audit | “The original adapter failed. Inspect the actual final acceptance and counterexample results, rather than assuming success. The independent local audit applies only to this Stripe policy.” |
| 2:10–2:30 | Repair proof, JSON/Markdown export | “This report binds the contract, fetched evidence and patch with hashes. Verified means these reported cases passed, not every possible response.” |
| 2:30–2:45 | Quickstart/repository | “Replay works without accounts; live mode uses private provider keys. PatchPilot stops explicitly on missing evidence or provider failure, and leaves deployment to a human reviewer.” |

If the live run fails, show the reason honestly and use a saved successful live run to inspect artifacts, identifying it as a prior run. Do not substitute replay under a live narration. The [successful reference](live-verification.json) and [latest attempt](evidence/live-latest-attempt.json) are separate records. Quota and model availability can change.

## Recording checklist

- Keep mode, target version, baseline and final scope legible.
- Show the real search query/source in the SerpApi version.
- Show actual account-backed partner artifacts in the NeatHack version.
- Capture desktop at a readable resolution; use deliberate pointer movement.
- Confirm exported report opens and repository is public.
- Add the actual video URL to [submission kit](submission-kit.md); no placeholder counts as an upload.
