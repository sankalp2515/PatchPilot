# PatchPilot submission design

## Outcome and scope
Ship a locally runnable, evidence-led API adapter repair agent and an honest public submission package for SerpApi and neatHack. Target buyer: SaaS integration engineers. Retain the restricted Python adapter interpreter, official-host research, protected cases, durable checkpoints and bounded repair budget. Do not claim arbitrary repository repair or production deployment.

## Product distinction
The repair proof binds the input contract, fetched version evidence, literal citations, baseline, proposed diff and independent verification. Add deterministic counterexample auditing of Stripe invoice payment pointers so a happy-path patch cannot silently accept a malformed payment. Report the additional coverage separately from user acceptance cases. An unproven result remains unverified.

## Experience
Serve an editorial landing page at `/` and the usable workspace at `/app`. Ink, warm paper and safety-orange accents express engineering inspection rather than generic AI styling. Lead with a working repair proof, show actual demo evidence, then workflow, benefits, scope, transparent experimental pricing, FAQ and install CTA. No fabricated customer logos, testimonials or savings. The workspace preserves existing workflows and makes sample replay, live credentials, custom incidents, result review and evidence export discoverable.

## Integrations
Use actual neatlogs WORKFLOW/TOOL/LLM spans with redacted metadata and real trace readback. Pin Python 3.12 because the SDK does not support Python 3.14. Verify Entire CLI local hooks and retain genuine checkpoint evidence; GitHub installation alone is insufficient. Build a cfo.ai scenario with editable assumption inputs and calculated pricing/cost/revenue/runway outputs, read back the resulting model and document assumptions. Never publish secrets or historical private transcripts.

## Delivery
One-command Windows and portable installation, offline replay, real-provider smoke, regression suites, responsive browser checks, professional README inspired by FactLedger's information hierarchy, architecture/data-flow/security/design rationale, verified sponsor evidence, judging assessment, and two ready-to-record demo scripts. Public posts and final event submission require the user's actual identity/video and must not be fabricated. Winning likelihood is unknown.
